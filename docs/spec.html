Pegana

Solana Peg Watchdog

Early-warning system para Liquid Staking Tokens e stablecoins em Solana. Compara valor intrínseco vs valor de mercado em tempo real, com lógica de peg-mechanism per-asset (fiat-backed, CDP, RWA-bearing, LST-backed, FX-cross), e dispara alertas multi-canal quando algum asset descola.

00 · Resumo executivo

O que o produto faz, em uma página

Sistema lê dados públicos do mainnet Solana (sem on-chain write, sem wallet com SOL, sem gas) e detecta descolamento entre o valor intrínseco/lastreado de um asset e seu valor de mercado. Cobre dois tipos de asset:

  • LSTs (Liquid Staking Tokens) — pegged a SOL via stake pool. Intrínseco = SOL lastreado por 1 LST.
  • Stablecoins — pegged a USD/BRL/EUR. Intrínseco depende do mecanismo (fiat, CDP, RWA, delta-neutral, FX).

Por que isso é uma classe única e não dois produtos

Apesar de assets diferentes, o modelo mental é o mesmo: oracle de discount. Cada asset tem (a) função que retorna seu valor intrínseco/target, (b) função que retorna seu valor de mercado, e (c) política de threshold. Tudo o resto (engine, DB, API, bot) é asset-class-agnostic. Cobrir os dois dobra o valor do produto sem dobrar a complexidade.

In scope (v1)

  • 14 assets: 7 LSTs (jitoSOL, mSOL, bSOL, INF, dSOL, bbSOL, JupSOL) + 7 stables (USDC, USDT, PYUSD, USDe, USDS, hyUSD, BRZ)
  • Adapter pattern com 5 estratégias de intrinsic: Sanctum LST, Fixed One, Pyth RR, Hylo on-chain, Pyth FX cross
  • Polling-based (sem gRPC streaming no v1) — cadência 15s, alertas em <30s
  • API pública REST + WebSocket sem auth
  • Telegram bot com subscribe/unsubscribe e thresholds custom
  • Token-2022 awareness (PYUSD usa o programa novo)

Out of scope (v1 — para v1.5+)

  • Yellowstone gRPC streaming (latência sub-segundo) → v1.5
  • Programa Solana on-chain pra publicar feed (tipo Pyth) → v2
  • Webhook signed channel → v1.5
  • Hedge/liquidation auto → fora de escopo
  • Frontend dashboard → desenvolvido em paralelo, fora deste spec

Não-objetivos

  • Não compete com Pyth/Switchboard — é derivative feed
  • Não é trustless on-chain — v1 é off-chain
  • Não tem latência sub-100ms — target: alerta <30s após cruzamento
  • Não monitora reservas off-chain de issuers (atestações Circle/Paxos etc) — apenas peg de mercado

Princípios de design

  1. Postgres é a verdade. Redis é cache/pub-sub descartável.
  2. Idempotência em toda escrita: snapshot key é (asset, source, ts) unique.
  3. Asset-class agnostic: engine, DB, API e bot tratam LST e stable iguais. Diferença é só no adapter.
  4. Sem state local: qualquer pod pode morrer e respawnar.
  5. Fail loud, recover silent: structured logs + Sentry on error, reconnect/retry automático.

3.1 Sanctum extra-api

Calculator on-chain de cada LST decodificado e exposto via HTTP gratuito. Confirmei ao vivo retornando {"jitoSOL": "1275866054", ...} (lamports por 1 LST). Uma chamada serve N LSTs. 

curl "https://extra-api.sanctum.so/v1/sol-value/current?lst=jitoSOL&lst=mSOL&lst=bSOL"

Cadência: 15s em condições normais, 3s em burst (LST em DRIFT).

3.2 Jupiter lite-api (keyless)

https://lite-api.jup.ag/swap/v1/quote — sem auth, 0.5 RPS. Pra 14 assets × 1 quote a cada 30s = 0.47 RPS, encaixa apertado. Estratégia: round-robin — cada tick polla 1 asset, com 14 ticks fechando o ciclo em 30s. 

curl "https://lite-api.jup.ag/swap/v1/quote\
?inputMint=<ASSET_MINT>\
&outputMint=<NUMERAIRE_MINT>\
&amount=<1_unit_in_smallest>\
&swapMode=ExactIn"
  • LST → numeraire = SOL (So11...112)
  • USD stable → numeraire = USDC (e USDC → USDT cross-check)
  • BRZ → numeraire = USDC (depois converte via Pyth USD/BRL)
Risco do lite-api

Limite de 0.5 RPS é apertado. Se Jupiter mudar (rate limit menor, deprecation), upgrade para Developer ($25). v1.5 já planeja isso. Mitigação no v1: round-robin + cache de 25s + backoff exponencial.

3.4 Public RPC (apenas para hyUSD)

hyUSD não tem feed de oracle nem API pública pra NAV. Solução: ler estado on-chain do programa Hylo Exchange + Stability Pool a cada 30s e computar CR.

  • RPC: https://api.mainnet-beta.solana.com (rate-limited mas free) ou https://solana-rpc.publicnode.com
  • Account read: getAccountInfo do state PDA do Exchange program
  • Decode com IDL puxada via anchor idl fetch HYEXCHtHkBagdStcJCp3xbbb9B7sdMdWXFNj6mdsG4hn
  • Fallback: https://api.llama.fi/protocol/hylo para TVL e health coarse

Algoritmo de CR para hyUSD

1. getAccountInfo(HYLO_EXCHANGE_STATE_PDA) → decode → list LST vaults + hyUSD supply
2. for each LST vault: Sanctum extra-api intrinsic + token balance → SOL backing per vault
3. total_sol_in_reserve = Σ vault_sol_backing
4. read Pyth SOL/USD → sol_price_usd
5. collateral_usd = total_sol_in_reserve × sol_price_usd
6. CR = collateral_usd / hyUSD_supply
7. intrinsic_hyusd_usd = min($1.00, CR × $1.00)
8. alert tiers:
   CR < 150% → DRIFT  (Stability Mode 1)
   CR < 130% → DEPEG  (Stability Mode 2 — pool drawing)
   CR < 110% → CRITICAL
   CR < 100% → BLACK_SWAN (intrinsic < $1)
04 · Adapter pattern

Estratégia per-asset em Rust

Coração da arquitetura asset-class-agnostic. Dois traits: IntrinsicSource (valor target) e MarketSource (preço efetivo). Cada asset declara qual implementação usar via config.

Traits

use async_trait::async_trait;
use rust_decimal::Decimal;

#[async_trait]
pub trait IntrinsicSource: Send + Sync {
    /// Returns the "should-be" value of 1 asset unit, in USD.
    async fn read(&self, ctx: &Ctx) -> Result<IntrinsicReading>;
}

#[async_trait]
pub trait MarketSource: Send + Sync {
    /// Returns the actual market value of 1 asset unit, in USD.
    async fn read(&self, ctx: &Ctx) -> Result<MarketReading>;
}

pub struct IntrinsicReading {
    pub value_usd: Decimal,
    pub source: &'static str,
    pub slot: Option<u64>,
    pub meta: serde_json::Value,  // e.g., CR for hyUSD
}

Implementações

SanctumLstIntrinsic (LSTs)

pub struct SanctumLstIntrinsic { pub symbol: String }

#[async_trait]
impl IntrinsicSource for SanctumLstIntrinsic {
    async fn read(&self, ctx: &Ctx) -> Result<IntrinsicReading> {
        let sol_value_lamports = ctx.sanctum.get_sol_value(&self.symbol).await?;
        let sol_value = Decimal::from(sol_value_lamports) / Decimal::from(1_000_000_000u64);
        let sol_usd = ctx.pyth.latest("SOL/USD").await?;
        Ok(IntrinsicReading {
            value_usd: sol_value * sol_usd,
            source: "sanctum+pyth",
            slot: None,
            meta: serde_json!({ "sol_per_lst": sol_value }),
        })
    }
}

pub struct FixedOneUsd;

HyloCrIntrinsic (hyUSD)

pub struct HyloCrIntrinsic {
    pub exchange_state_pda: Pubkey,
}

#[async_trait]
impl IntrinsicSource for HyloCrIntrinsic {
    async fn read(&self, ctx: &Ctx) -> Result<IntrinsicReading> {
        let state = ctx.rpc.get_account_data(&self.exchange_state_pda).await?;
        let exch = HyloExchange::deserialize(&state)?;
        let sol_usd = ctx.pyth.latest("SOL/USD").await?;

        let mut total_sol_reserve = Decimal::ZERO;
        for vault in &exch.lst_vaults {
            let sol_per_lst = ctx.sanctum.get_sol_value(&vault.symbol).await?;
            total_sol_reserve += Decimal::from(vault.balance) * sol_per_lst;
        }
        let collateral_usd = total_sol_reserve * sol_usd;
        let hyusd_supply = Decimal::from(exch.hyusd_supply);
        let cr = collateral_usd / hyusd_supply;

        let intrinsic = if cr >= Decimal::ONE { Decimal::ONE } else { cr };
        Ok(IntrinsicReading {
            value_usd: intrinsic,
            source: "hylo_cr",
            slot: Some(ctx.rpc.last_slot()),
            meta: serde_json!({ "cr": cr, "reserve_sol": total_sol_reserve }),
        })
    }
}

PythFxCross (BRZ)

pub struct PythFxCross { pub fx_feed: String, pub invert: bool }

#[async_trait]
impl IntrinsicSource for PythFxCross {
    async fn read(&self, ctx: &Ctx) -> Result<IntrinsicReading> {
        let rate = ctx.pyth.latest(&self.fx_feed).await?;
        let value = if self.invert { Decimal::ONE / rate } else { rate };
        Ok(IntrinsicReading { value_usd: value, source: "pyth_fx", slot: None, meta: Default::default() })
    }
}

MarketSource (universal)

pub struct JupiterUsdMarket {
    pub asset_mint: Pubkey,
    pub asset_decimals: u8,
    pub numeraire_mint: Pubkey,   // SOL or USDC
    pub numeraire_to_usd: String, // Pyth feed for numeraire/USD
}

#[async_trait]
impl MarketSource for JupiterUsdMarket {
    async fn read(&self, ctx: &Ctx) -> Result<MarketReading> {
        let one_unit = 10u64.pow(self.asset_decimals as u32);
        let quote = ctx.jupiter.quote(self.asset_mint, self.numeraire_mint, one_unit).await?;
        let numeraire_usd = ctx.pyth.latest(&self.numeraire_to_usd).await?;
        let value_usd = quote.to_decimal() * numeraire_usd;
        Ok(MarketReading { value_usd, price_impact_pct: quote.price_impact, route: quote.label })
    }
}

Round-robin scheduler

Para respeitar 0.5 RPS do Jupiter lite-api, cada tick polla 1 asset. Com 14 assets e tick de ~2.2s, fechamos ciclo em 30s para cada asset. 

async fn run_jupiter_loop(ctx: Arc<Ctx>, assets: Vec<Arc<Asset>>) {
    let mut idx = 0usize;
    let mut ticker = tokio::time::interval(Duration::from_millis(2200));
    loop {
        ticker.tick().await;
        let asset = &assets[idx % assets.len()];
        idx += 1;

        if let Err(e) = poll_market(&ctx, asset).await {
            tracing::warn!(asset = %asset.symbol, ?e, "jupiter poll failed");
            record_failure(&ctx.metrics, asset).await;
        }
    }
}

Sanctum batch loop

Uma chamada serve todos os LSTs. Cadência 15s.

async fn run_sanctum_loop(ctx: Arc<Ctx>, lsts: Vec<String>) {
    let mut ticker = tokio::time::interval(Duration::from_secs(15));
    loop {
        ticker.tick().await;
        match ctx.sanctum.batch_sol_value(&lsts).await {
            Ok(map) => for (sym, lamports) in map {
                persist_intrinsic(&ctx, &sym, lamports).await;
                ctx.redis.publish("watchdog:src:sanctum", &sym).await;
            },
            Err(e) => tracing::warn!(?e, "sanctum batch failed"),
        }
    }
}

06 · Engine

engine-rs

Consumidor primário do Redis pub/sub. Mantém em memória HashMap<Symbol, AssetState> e a cada update recomputa discount usando a estratégia certa do adapter, aplica EWMA, transiciona estado.

Fórmulas per asset class

# LSTs + Stables genéricos
discount_raw    = 1 - (market_usd / intrinsic_usd)
discount_smooth = α · discount_raw + (1-α) · prev   [EWMA, α=0.3]

# Oracle cross-check (quando feed Pyth existe)
oracle_implied_value = pyth_lst_usd_price
oracle_discount      = 1 - (oracle_implied_value / intrinsic_usd)
confidence = |discount_smooth - oracle_discount| < 0.005 ? "high" : "low"

# hyUSD (CR-based)
cr = collateral_usd / hyusd_supply
state =
  PEGGED      if cr >= 1.50
  DRIFT       if 1.30 <= cr < 1.50
  DEPEG       if 1.10 <= cr < 1.30
  CRITICAL    if 1.00 <= cr < 1.10
  BLACK_SWAN  if cr < 1.00
discount = max(0, 1 - cr)  # se under-collateralized

State machine (geral, não-hyUSD)

PEGGED
|d| < drift
DRIFT
drift ≤ |d| < depeg
DEPEG
depeg ≤ |d| < critical
CRITICAL
|d| ≥ critical

Thresholds default per class

ClassDriftDepegCriticalRacional
LST0.20%1.00%3.00%LSTs tipicamente em ±0.1% sem stress
Stable fiat (USDC/USDT/PYUSD)0.15%0.50%2.00%Mercado super líquido; 0.5% já é evento
Stable delta-neutral (USDe)0.25%1.00%3.00%Mais risk; basis trade pode descolar
Stable CDP (USDS)0.20%0.75%2.50%Hybrid risk
Stable LST-CDP (hyUSD)CR-based: 150% / 130% / 110% / 100% black-swanMecanismo diferente
Stable FX (BRZ)1.00%3.00%8.00%BRL é mais volátil que USD; thresholds maiores

Hysteresis

  • Sobe de estado: 30s consecutivos acima do threshold (10 samples a 3s)
  • Desce de estado: 120s consecutivos abaixo (evita flapping)
  • Buffer per-asset em memória + snapshot no Redis a cada 10s (recover state)
