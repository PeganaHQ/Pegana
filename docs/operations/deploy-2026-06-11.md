## 0. Goal

After this deploy:

1. Calibration v1 verdict per [ADR-0015](../adr/0015-calibration-v1-per-class-verdict.md)
   (per-class rule, supersedes ADR-0001) is computed mechanically against
   the post-evidence window (the early deploy went live 2026-05-29 03:55
   UTC per ADR-0005, so the window is 05-29 → 06-10) and recorded as `SHIP`
   (or `TUNE`/`EXTEND` → launch slips).
2. Each Phase 0 asset (JupUSD / JLP / EURC / dzSOL / vSOL) is either
   flipped `active = true` in `assets.toml` OR deferred per
   [ADR-0002](../adr/0002-per-asset-activation-rule.md) with the comment
   `# deferred per ADR-0002 on 2026-06-11`.
3. `FEATURE_PUBLIC_ALERTS=true` — flips on the **public read surface**: the
   dispatcher starts including `evidence_url` in the human-readable webhook +
   Telegram copy, and the public `/v1/audit` index + `/v1/alerts` + `/v1/audit.csv`
   go live (the web `audit.xml` / `feed/events.xml` feeds then populate from them).
   Note: `evidence_url` is stamped into the evidence record **unconditionally**
   (the flag does not gate stamping), and `/audit/[id]` detail + `/onchain` are
   **already live** (ungated direct lookup) — see ADR-0020. The flag's job is to
   keep the *index/feed* of the calibration ledger quiet until launch.
4. Releases tagged: `methodology-v0.1.0` and
   `pegana-replay-cli-v0.1.0`. cargo-dist CI fires, GitHub Releases
   gets Sigstore-attested binaries, `releases.pegana.xyz` mirror
   refreshes.
5. Launch tweet + Farcaster + reply thread posted per
   `docs/launch/twitter-copy-launch.md`.

## 3. Deploy + flip (T-0)

```bash
# 1. SSH
ssh ${PEGANA_DEPLOY_SERVER}
cd ~/pegana

# 2. Pull
git fetch origin
git log --oneline origin/main -5
git checkout main && git pull --ff-only

# 3. Migrations (idempotent — most already applied on the 05-29 early deploy).
# ⚠️ The 'xtask' compose service does NOT exist. Apply migrations directly via
# psql (same loop as the canonical launch-runbook § 2 step 3):
docker compose cp migrations postgres:/tmp/migrations
for m in $(ls migrations/*.sql | sort); do
  basename=$(basename "$m")
  echo "Applying $basename..."
  docker compose exec -T postgres sh -c \
    "psql -U \$POSTGRES_USER \$POSTGRES_DB -v ON_ERROR_STOP=1 -f /tmp/migrations/$basename" \
    || echo "(may already be applied — verify manually if errors)"
done

# 4. Rebuild + recreate only the services that changed
docker compose up -d --build api engine dispatcher bot mcp-ts

# 5. Wait for /ready
for svc in api engine dispatcher; do
  echo "=== $svc ==="
  docker compose exec -T $svc curl -s http://localhost:8080/ready || true
done

# 6. FLIP THE FLAG
grep FEATURE_PUBLIC_ALERTS ~/pegana/.env
# If false (expected from 06-01):
sed -i 's/^FEATURE_PUBLIC_ALERTS=false/FEATURE_PUBLIC_ALERTS=true/' ~/pegana/.env
grep FEATURE_PUBLIC_ALERTS ~/pegana/.env
# Expected: FEATURE_PUBLIC_ALERTS=true

# 7. Recreate the services that read the flag.
# ⚠️ `docker compose restart` does NOT reload `env_file: .env`. For an env-only
# change (the flag flip) you MUST force-recreate, then verify it loaded:
docker compose up -d --force-recreate api dispatcher bot
docker compose exec -T bot sh -c "env | grep FEATURE_PUBLIC_ALERTS"
# Expected: FEATURE_PUBLIC_ALERTS=true
```

## 4. Tag the releases (T+10m)

> ⚠️ **cargo-dist + `release.yml` live in the PUBLIC `pegana-replay` repo, NOT
> the private `pegana` repo.** Pushing a tag to `origin` (private `pegana`) does
> **not** fire the binary build — the private repo has no release workflow and
> (per memory) the public repo's GitHub Actions are currently blocked on a
> billing-quota reset. The release is driven from the public mirror after the
> subtree sync. The `git tag -a -m` commands below run **locally on the laptop**
> (where `user.email` IS set) — the lightweight-tag footgun only applies on
> Hetzner, so it does not apply here.

```bash
# Local, in the worktree (private repo). These tags mark the source commit but
# do NOT themselves trigger cargo-dist:
cd ~/Desktop/Projetos/pegana

# Methodology release — gates the engine + crates.io publish
git tag -a methodology-v0.1.0 -m "Trust Layer v0.1.0 methodology release"

# Replay CLI release — gates the cargo-dist binary build
git tag -a pegana-replay-cli-v0.1.0 -m "pegana-replay CLI v0.1.0 — offline replay"

git push origin methodology-v0.1.0 pegana-replay-cli-v0.1.0

# The binary build is driven from the PUBLIC pegana-replay repo: sync the
# subtree, then tag/release THERE so its release.yml (cargo-dist) fires.
# See the public-repo carve-out resume sequence (memory:
# project_repo_split_pegana_replay) — GitHub Actions billing must be unblocked
# first.
```

cargo-dist CI fires (5-10 min) **in the public `pegana-replay` repo** once its
Actions are unblocked:
- Builds 4-platform binaries (linux x86_64/aarch64, macOS x86_64/aarch64)
- Publishes to GitHub Releases
- Attaches Sigstore attestations (`gh attestation verify` passes)
- `releases.pegana.xyz` mirror reflects automatically

Verify on your laptop (note `--repo` points at the public mirror):

```bash
gh release view pegana-replay-cli-v0.1.0 --repo lrafasouza/pegana-replay
gh release download pegana-replay-cli-v0.1.0 --repo lrafasouza/pegana-replay -p 'pegana-replay-x86_64-linux*'
gh attestation verify pegana-replay-x86_64-linux \
  --owner lrafasouza --repo pegana-replay
# Expected: ✓ attestation verified

curl --proto '=https' --tlsv1.2 -LsSf \
  https://releases.pegana.xyz/pegana-replay-installer.sh | sh
~/.pegana/bin/pegana-replay --version
# Expected: 0.1.0
```

## 5. Smoke tests (T+15m)

Run from your laptop. Defer to the launch-runbook § 3 for the full
suite. Minimum gate:

```bash
# Marketing landing
curl -sI https://pegana.xyz | head -1                       # HTTP/2 200

# Trust strip endpoints
curl -s https://pegana.xyz/api/methodology | jq '{version,status}'
# Expected: { "version": "0.1.0", "status": "active" }

# Audit endpoint + replay bundle for most recent alert
ID=$(curl -s https://api.pegana.xyz/v1/audit?limit=1 | jq -r '.[0].id')
curl -sI "https://api.pegana.xyz/v1/audit/$ID"              # 200
curl -sI "https://api.pegana.xyz/v1/audit/$ID/replay-bundle" # 200
curl -sI "https://api.pegana.xyz/v1/audit/$ID/onchain"      # 200 or 202

# OpenAPI spec reflects the post-launch asset count
curl -s https://api.pegana.xyz/openapi.json | jq '.info.description'

# Offline replay of a real production alert
pegana-replay --alert-id "$ID"
# Expected: ✓ PASS
```

Any non-200 from a 200-expected endpoint = halt the launch and consult
the launch-runbook § 4 rollback section.

## 8. 24h watch list

Open `https://grafana.pegana.xyz/d/pegana-overview`. Pin in order
(per launch-runbook § 5):

1. Engine publish rate — > 0 sustained
2. Audit persist rate by outcome — `failed` line at zero
3. Audit persist latency p99 — < 0.05s
4. On-chain commit outcomes — `ok` dominates, `rpc_error` < 5%
5. Commit wallet balance — > 0.5 SOL (auto-refund threshold)
6. Commit queue depth — non-zero
7. Methodology broken (startup refusals) — must be 0
8. Receipt hash fallback (total) — must be 0
9. API rate-limited requests — < 1/s sustained outside `/v1/assets`
10. Retractions dispatched — should be 0 during launch
11. WS clients — climbing through the day

Refresh: 30s for the first hour, then 5m. Time range: now-1h, then
now-6h once stable.

## 9. Rollback (if anything fails)

Defer to [`launch-runbook-2026-06-11.md`](./launch-runbook-2026-06-11.md) § 4.
Quick reference:

```bash
ssh ${PEGANA_DEPLOY_SERVER}
cd ~/pegana

# 1. Flip flag back FIRST (stops user-visible noise).
#    env_file change → force-recreate, NOT restart.
sed -i 's/^FEATURE_PUBLIC_ALERTS=true/FEATURE_PUBLIC_ALERTS=false/' ~/pegana/.env
docker compose up -d --force-recreate api dispatcher bot

# 2. Roll back binaries
git checkout pre-trust-layer-launch
docker compose up -d --build api engine dispatcher bot

# 3. DO NOT roll back Postgres migrations — they are additive.
```

If rollback itself fails, stop the bot first
(`docker compose stop bot`) — quiet failure > noisy incorrect alerts.
