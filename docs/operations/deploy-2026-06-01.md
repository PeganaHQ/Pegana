# Deploy 2026-06-01 — dogfood prod cut (FEATURE_PUBLIC_ALERTS=false)

> One-pager for the Phase 3 early evidence rollout per
> [ADR-0005](../adr/0005-early-evidence-rollout.md). Public surface stays
> dark; persistence + on-chain commits go live so the back half of the
> calibration window produces verifiable, replayable data the launch
> verdict can cite.
>
> Owner on call: Rafael. Estimated window: ~45 minutes.

## 0. Goal

After this deploy, every alert emitted between 2026-06-01 and 2026-06-10
must:

1. Land a row in `alert_evidence` with `methodology_version='0.1.0'`.
2. Get an on-chain commit attempt (`alert_evidence.onchain_tx_sig`
   populated within ~30s, or row recorded in
   `alert_evidence_commit_failures`).
3. Have a working `/v1/audit/<id>` and `/v1/audit/<id>/replay` response.
4. Stay invisible to the public — `FEATURE_PUBLIC_ALERTS` remains
   `false`; dispatcher does not emit `evidence_url` in webhook /
   Telegram payloads yet.

The 06-11 launch one-pager ([`deploy-2026-06-11.md`](./deploy-2026-06-11.md))
takes over from there.

## 2. Deploy steps (T-0)

Per [memory: deploy workflow](../../README.md) — SSH directly, no script.

```bash
# 1. SSH (canonical address from operator memory)
ssh ${PEGANA_DEPLOY_SERVER}

# 2. Pull
cd ~/pegana
git fetch origin
git log --oneline origin/main -5       # sanity-check the expected commit
git checkout main && git pull --ff-only

# 3. Apply migrations in lexical order via psql.
#    ⚠️ The 'xtask' compose service does NOT exist — apply directly with psql
#    (same loop as launch-runbook § 2 step 3). Already-applied ones error
#    harmlessly; ON_ERROR_STOP keeps a *new* migration's failure visible.
#    Order documented for the deploy log:
#      0028 alert_evidence
#      0029 alert_events_view              (may already be on prod, see pre-deploy-notes-trust-layer.md)
#      0030 methodology_versions           (inserts 0.1.0 seed row)
#      0031 alert_evidence_onchain_sig
#      0032 retractions
#      0033 commit_status_and_failures
#      0034 alert_evidence_pending
#      0035 engine_state_snapshot
#      0036 mcp_call_log
#      0037 block_truncate                 (PL/pgSQL trigger; idempotent)
#      0038 webhook_deliveries_alert_id_idx (CREATE INDEX IF NOT EXISTS)
docker compose cp migrations postgres:/tmp/migrations
for m in $(ls migrations/*.sql | sort); do
  basename=$(basename "$m")
  echo "Applying $basename..."
  docker compose exec -T postgres sh -c \
    "psql -U \$POSTGRES_USER \$POSTGRES_DB -v ON_ERROR_STOP=1 -f /tmp/migrations/$basename" \
    || echo "(may already be applied — verify manually if errors)"
done

# 4. Wire the commit key into the env (one-time; skip if already present)
grep -q PEGANA_COMMIT_KEYPAIR ~/pegana/.env \
  || echo "PEGANA_COMMIT_KEYPAIR=/opt/pegana/.secrets/commit-keypair.json" >> ~/pegana/.env
grep -q AUDIT_BASE_URL ~/pegana/.env \
  || echo "AUDIT_BASE_URL=https://pegana.xyz" >> ~/pegana/.env

# 5. CONFIRM the public flag is still false. Per ADR-0005, only Phase 13 flips it.
grep FEATURE_PUBLIC_ALERTS ~/pegana/.env
# Expected: FEATURE_PUBLIC_ALERTS=false   (or unset, which defaults to false)
# If true: STOP, edit it back to false BEFORE the restart in step 6.

# 6. Build the new images with the git SHA baked in (per Phase 13 Task 13.1 Step 6)
GIT_SHA=$(git rev-parse HEAD)
docker compose build --build-arg PEGANA_GIT_SHA="$GIT_SHA" engine api dispatcher

# 7. Roll only the services that changed
docker compose up -d engine api dispatcher mcp-ts bot

# 8. Wait for /ready on each service
for svc in api engine dispatcher; do
  echo "=== $svc ==="
  docker compose exec -T $svc curl -s http://localhost:8080/ready || true
done
```


## 4. Rollback (if anything fails)

Per ADR-0005, the additive migrations are safe to leave in place if the
binary needs to roll back — alerts written under the new code stay, the
engine just stops writing new evidence rows.

```bash
ssh ${PEGANA_DEPLOY_SERVER}
cd ~/pegana

# 1. Rewind to the rollback tag
git checkout pre-dogfood-2026-06-01
docker compose up -d --build engine api dispatcher mcp-ts bot

# 2. ONLY if the engine refuses to start because of the methodology check:
#    drop the seed row, restart, file a ticket.
docker compose exec postgres psql -U "$POSTGRES_USER" "$POSTGRES_DB" \
  -c "UPDATE methodology_versions SET status='deprecated' WHERE version='0.1.0';"

# 3. LAST RESORT (data loss; only if migrations themselves are the failure):
#    per Phase 13 plan § Rollback procedure.
docker compose exec postgres psql -U "$POSTGRES_USER" "$POSTGRES_DB" <<'SQL'
DROP TABLE IF EXISTS alert_evidence_commit_failures CASCADE;
DROP TABLE IF EXISTS alert_evidence_pending CASCADE;
DROP TABLE IF EXISTS alert_evidence CASCADE;
DROP TABLE IF EXISTS methodology_versions CASCADE;
DROP TABLE IF EXISTS retractions CASCADE;
DROP TABLE IF EXISTS engine_state_snapshot CASCADE;
DROP TABLE IF EXISTS mcp_call_log CASCADE;
-- alert_events view is harmless to keep
SQL
```

## 5. Monitoring — first 4 hours

Open `https://grafana.pegana.xyz/d/pegana-overview`. Watch these panels
specifically (subset of the 06-11 launch list since the public surface
is still off):

| Panel | What healthy looks like during the dogfood window |
|---|---|
| **Audit persist rate by outcome** | `ok` line tracks the engine publish rate within ±1; `failed` line at zero |
| **Audit persist latency p50/p95/p99** | p99 < 0.05s |
| **On-chain commit outcomes** | `ok` dominates within ~30s of each alert; `rpc_error` < 5% sustained |
| **Commit wallet balance (SOL)** | Decreases by ~0.0001 per alert; refill threshold = 0.5 SOL |
| **Commit queue depth** | Non-zero (permits available); 0 = saturated |
| **Methodology broken (startup refusals)** | 0 (any value > 0 is a deploy-blocking incident) |
| **Receipt hash fallback (total)** | 0 |

Sentry: if `pegana_audit_persist_failed_total > 0` or
`pegana_receipt_hash_fallback_total > 0` fires, investigate the trace
immediately — every event compromises one calibration data point.
