# ADR-0039 — NAV discount-sanity yields to a confirmed BLACK_SWAN

- **Status:** Accepted (2026-07-18). Built on `landing/v2-port` in the staged (unpublished) **methodology 0.7.0** bundle, 1:1 + adversarially validated (relaunch 1:1 sweep), **NOT deployed**. Folds into 0.7.0 — no new version bump (prod tops at 0.6.1; nothing published yet).
- **Relationship to ADR-0030/0025:** ADR-0025 added the reachable-from-spread BLACK_SWAN band (the publicly-advertised 5th state, "a UST-style CRITICAL→BLACK_SWAN cascade"). ADR-0030 added the discount-side NAV-sanity guard (`NAV_DISCOUNT_SANITY_BPS = 3000`) to mask a garbage-HIGH intrinsic (the JLP `JLP/USD.RR` 6400× misprint → false BLACK_SWAN). This ADR resolves the **collision between the two**: the guard was masking the very BLACK_SWAN band ADR-0025 exists to surface.
- **Decision owner:** Claude (relaunch cycle), founder-ratified via the "faça tudo completo" mandate.

## Context

`discount_sanity_violated(class, discount)` fires for any direction-sensitive asset (LST / StableYield) whose smoothed discount exceeds `NAV_DISCOUNT_SANITY_BPS = 3000` (30%), and the override was applied **unconditionally after** `transition_decide` in both the live engine (`main.rs`) and `rederive.rs`:

```
if premium_sanity || discount_sanity || pyth_gate || intrinsic_gate { final_state = Unknown }
```

For **JLP** the default `black_swan` band is `critical * 2 = 1500 * 2 = 3000` bps — **numerically identical** to the sanity ceiling. So a discount of 3100 bps classifies BLACK_SWAN (`3100 >= 3000`) *and* trips `discount_sanity_violated` (`3100 > 3000`) simultaneously → forced UNKNOWN. The true BLACK_SWAN window was ~1 bps wide before flipping back to UNKNOWN. For **sUSD/ONyc** (`black_swan = 1600`) a genuine collapse past 30% was masked the same way.

Worse than a flap: the engine's `force_unknown()` wipes `candidate_since` **every tick**, so the BLACK_SWAN confirm window (`CONFIRM_UP_SECS`) could never complete — a sustained real >30% collapse was masked as UNKNOWN **forever**. During the worst crisis an LST/yield-stable can have — the exact scenario the oracle exists to call — the public feed showed `UNKNOWN` ("price below NAV looks unreliable — check the feed"), actively misleading consumers into reading a real depeg as a data-quality problem.

The ADR-0030 test suite only exercised 7/15/25% depegs (which classify fine) and the single-sample 9998 bps garbage feed (correctly masked) — never a **sustained >30% direction-sensitive collapse**, so the gap shipped uncaught. Found by the relaunch 1:1 sweep.

The core tension: a flat magnitude cutoff **cannot** separate a garbage-HIGH NAV print from a real total collapse — both live in the 30–99% band (UST went to ~99%). The only distinguishing signal already available is **persistence**, which the confirm window measures.

## Decision

Discount-sanity **yields to a hysteresis-confirmed BLACK_SWAN**. Persistence, not magnitude, is the distinguisher.

- **Publish gate (engine + rederive, byte-exact parity):** the discount-sanity override fires only when the move has **not** confirmed BLACK_SWAN:
  ```
  discount_sanity_violated(class, discount) && final_state != BlackSwan
  ```
  Once the FSM commits BLACK_SWAN (the extreme discount survived `CONFIRM_UP_SECS`), it is a real, time-validated catastrophe — published as BLACK_SWAN, not downgraded. `rederive.rs` mirrors this exactly; `final_state` there is `transition_decide`'s committed state from the same frozen inputs, so re-derivation stays byte-exact.
- **Maturation (engine only):** while a BLACK_SWAN candidate is maturing, publish honest-dark UNKNOWN **but do not `force_unknown()`** (which would reset `candidate_since` and prevent confirmation). Only hard-reset when the raw candidate is *below* BLACK_SWAN — a future asset whose `black_swan` band sits above the sanity bound, where there is no maturing catastrophe to protect. A transient garbage print self-clears next tick (the candidate drops, `transition_decide` Case 1 clears it); a sustained collapse confirms and is surfaced.
- **Premium side unchanged:** a premium (discount < 0) is never a BLACK_SWAN candidate on the discount side, so `premium_sanity_violated` keeps its unconditional override.
- **Observability:** new counter `pegana_engine_nav_sanity_blackswan_confirmed_total` — a discount beyond the sanity bound that nonetheless published BLACK_SWAN. Kept distinct from `pegana_engine_nav_sanity_unknown_total{side="discount"}` so dashboards tell a masked bad print apart from a surfaced real catastrophe.

## Consequences

- **A real >30% collapse now surfaces BLACK_SWAN** after the confirm window, instead of being masked as UNKNOWN forever. The product finally calls the catastrophe it exists to call.
- **The confirm window IS the corroboration.** A transient garbage print (single/few bad samples) shows UNKNOWN during the window and self-clears — the ADR-0030 protection is preserved for its actual failure mode.
- **Accepted residual:** a garbage NAV feed that stays broken **continuously past `CONFIRM_UP_SECS`** would now confirm BLACK_SWAN. This is a pathological, independently-alertable condition.
- **AMENDMENT (2026-07-18, P1 audit) — the carve-out is EXTENDED to ALL three gates.** The original text above claimed the Pyth confidence-gate (ADR-0032) and intrinsic-liveness gate (ADR-0038) were *orthogonal* feed-quality protection and could stay unconditional. **That was wrong and reopened the exact bug this ADR closes, via a side door.** Per Pyth's own best-practices docs (verified via context7), a **wide confidence interval is the documented signature of high volatility / publisher disagreement** — i.e. it is *correlated* with the very crash a BLACK_SWAN represents, not orthogonal to it. During a market-wide collapse the shared numéraire feed's (SOL/USD) confidence widens for every jupiter_usd-priced asset simultaneously; the unconditional `pyth_confidence_gate_violated` branch then `force_unknown`-wiped the just-confirmed BLACK_SWAN's `candidate_since` every tick → masked forever, exactly as before. The intrinsic-liveness gate had the identical dormant gap. **Fix:** the override logic is now the single shared `methodology::override_final_state`, which exempts a hysteresis-confirmed BLACK_SWAN from ALL THREE feed/value gates (only premium-sanity — which cannot co-occur with a discount-driven BLACK_SWAN — stays unconditional). All THREE implementations now derive the published state from this one function: `rederive` and the xtask backtest runner **call** it directly; the live engine `try_recompute` **calls its attributed sibling `override_final_state_attributed`** (identical gate order + carve-out, additionally returning an `OverrideReason` the engine keys its `force_unknown`/metrics/`state_reason` side-effects off — so it never re-derives the gate order). The engine's earlier hand-rolled `if/else-if` chain was replaced 2026-07-18 (audit-review follow-up); golden backtest byte-exact (no drift), so the published verdicts are unchanged — the "three implementations agree by construction" invariant is now structurally enforced, not merely proven empirically by the e2e. New methodology tests lock the attribution + wrapper agreement + the all-gates carve-out (`attributed_*`). New regression tests: `confirmed_blackswan_survives_wide_pyth_confidence`, `maturing_blackswan_with_wide_pyth_is_unknown`, `confirmed_blackswan_survives_stale_intrinsic`. Golden byte-exact (no fixture reaches BLACK_SWAN).
- **AMENDMENT 2 (2026-07-18, audit-review) — the carve-out now covers the LAST gate too (premium-sanity).** The prior amendment left `premium_sanity` unconditional, arguing it "cannot co-occur with a discount-driven BLACK_SWAN." That is true for the **raw candidate** (a premium classifies to PEGGED, never a BlackSwan candidate) but **false for the committed state**: a single garbage-LOW NAV print during a confirmed catastrophic DISCOUNT collapse reads as a huge apparent **PREMIUM** (market ≫ broken NAV) via the EWMA, while `final_state` is still the committed BLACK_SWAN from prior ticks. The unconditional `premium_sanity` branch then re-masked that confirmed catastrophe as UNKNOWN and reset the FSM — the exact bug this ADR closes, through the one remaining open gate. **Fix:** `premium_sanity` moved inside the same `final_state != BlackSwan` guard as the other three, so **all four** gates now yield to a confirmed BLACK_SWAN. The market reality (crashed) is unchanged by a NAV glitch, so the confirmed collapse survives. Premium has no maturation nuance (it is never a BlackSwan candidate), so the engine's `force_unknown` on the premium arm is reached only for non-BlackSwan states. Golden byte-exact (no drift); `attributed_confirmed_blackswan_is_exempt_from_all_feed_gates` updated to assert premium yields over a committed BlackSwan but still masks a non-BlackSwan.
- **Recovery is faster:** a discount-sanity trip no longer resets the FSM to UNKNOWN, so once the reading normalizes the asset returns to its real state on the next tick rather than decaying out of a forced UNKNOWN.
- **Tests:** 3 new `rederive` tests lock `confirmed → BLACK_SWAN`, `maturing → UNKNOWN`, `first-sighting → UNKNOWN` (JLP-like thresholds: `critical=1500 → black_swan=3000`, the exact collision). Golden byte-exact (the fix is inert on the USDe fixture — no direction-sensitive >30% move there).
