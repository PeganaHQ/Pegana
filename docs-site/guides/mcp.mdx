[Model Context Protocol](https://modelcontextprotocol.io) (MCP) is the standard
agents use to discover and call tools. Pegana ships an MCP server that exposes peg
state, history, methodology metadata, and a live event subscription — directly to
the model, without needing a wrapper API call.

**Hosted endpoint:** `https://mcp.pegana.xyz` (Streamable HTTP transport)
**Source:** [`mcp-ts/`](https://github.com/PeganaHQ/Pegana/tree/main/mcp-ts) (TypeScript on Bun + Hono)

Point your MCP host at the URL — no install, no clone, no API key. See
[setup](/guides/mcp-setup-claude) for per-host config.

## Why MCP

If your agent already lives in Claude Code, Cursor, Cline, or Continue, MCP is the
shortest path to "the model knows the peg state." No middleware, no toolchain — the
model calls `get_asset_state("USDC")` and gets back JSON.

The model also discovers methodology and asset metadata via `get_methodology` and
`get_assets`, so it can reason about *why* an alert fires before reading any code you
wrote.

## A typical agent prompt

Once configured:

```text
You have a Pegana MCP server. Before recommending any swap to or from a
pegged asset on Solana, call get_asset_state({symbol}) and refuse if the
state is not PEGGED (unless the user explicitly accepts the risk).
```

The model handles the rest. It will call `get_asset_state("USDC")` on its own,
inspect the result, and refuse a swap if state is `DRIFT` or worse.

## Tool list

| Tool | Description |
| --- | --- |
| `ping` | Server liveness check |
| `get_assets` | List all active assets with latest snapshot |
| `get_asset_state` | Current state, discount, intrinsic and market price for one asset |
| `get_methodology` | This asset's intrinsic and market sources plus the state machine, for the model to reason from |
| `get_loop_exposure` | Anonymous aggregate leverage/health-factor exposure for Kamino & Jupiter Lend (k-anonymity k≥5) |
| `simulate_depeg_impact` | Estimated liquidatable collateral (`liquidatable_usd`, `positions`) across Kamino and Jupiter Lend for a preset depeg shock |
| `verify_alert` | Verify an alert receipt (hash + optional on-chain anchor) — proxies `GET /v1/audit/:alert_id`, data already public |
| `ping_paid` | Legacy alias of `ping` (free; returns `paid pong`) |
| `get_asset_history` | Bucketed discount history (1m/5m/15m/1h), up to 30 days |
| `subscribe_peg_events` | Pull state transitions since a cursor timestamp |

## Hosted — no clone needed

The server is hosted at `mcp.pegana.xyz`, so there is nothing to clone or install and
no API key: point your MCP host at the URL (see [setup](/guides/mcp-setup-claude)). The
runtime is [`mcp-ts/`](https://github.com/PeganaHQ/Pegana/tree/main/mcp-ts) (TypeScript
on Bun + Hono), configured via env vars (`PEGANA_API`, `REDIS_URL`, `DATABASE_URL`).

## Anti-prompt-injection note

The MCP server returns structured JSON: no markdown, no nested instructions, no
"ignore previous" payloads. The only caller-supplied string echoed back is the
`symbol` (or `alert_id`) you passed, in `get_methodology`'s output and in error texts;
it is length-capped by the input schema (20 characters for symbols, a UUID for alert
IDs). For every asset in the registry, the `get_methodology` content is compiled into
the server at build time, so an attacker compromising `api.pegana.xyz` cannot inject
prompts via the methodology response.

The values we *do* return (`asset`, `state`, decimal numbers, timestamps) are
constrained shapes — your model can treat them as data, not prompts.
